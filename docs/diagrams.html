🏗️ mini-sor 시스템 다이어그램

1. 전체 시스템 구조

FEP를 통한 거래소 프로세스 분리 (Phase 12)

구조: 화면 ↔ 채널계 ↔ 원장 → SOR → FEP → 거래소 프로세스

2. 주문 처리 흐름 (7단계)

SOR 배분에서 체결까지 (p50: 351ns)

지연: 전 구간 p50 351ns | 저널 끔 기준 | 가장 비싼 단계: SOR 계획 (50%)

3. API 통신 흐름

화면 → 채널계 → 원장 → 체결 → 방송

동기: 주문 → 전문 → 체결 (파란선) | 비동기: 체결 → WebSocket (회색) | 응답: 200 OK + 체결정보

4. 데이터 흐름

시장 데이터 → 통합 호가 → 매칭 → 화면

입력: KRX + NXT + 실시세(선택) → 통합 호가 | 처리: 최선집행 → 매칭 | 출력: 체결 기록 + WebSocket 방송

5. 주문 상태 전환

접수 → 체결 → 정산 (또는 취소/거절)

주요 경로: 접수 → 체결 → 정산 | 대안: 취소(사용자) 또는 거절(원장: 증거금/호가 등) | 부분 체결에서 더 체결 가능
