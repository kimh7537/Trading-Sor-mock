# Track B — 백테스트 연동

> TASKS.md의 Phase 5를 대체·보완하는 별도 트랙.
> **Phase 2(SOR) 완료 시점부터 착수 가능하다.** 원장·FEP(Phase 3)는 필요 없다.

---

## 이 트랙의 목적

알고리즘 트레이딩 전략의 백테스트에서 **낙관적 체결 가정을 제거한다.**

실거래 주문은 토스증권 API가 처리하고, 증권사가 자체 SOR로 시장을 배분한다.
따라서 mini-sor는 실거래 경로에 끼지 않는다. 쓰임새는 실거래 **이전** 단계다.

| 역할 | 내용 |
|---|---|
| 체결 시뮬레이터 | 백테스트의 체결 계층을 교체. 슬리피지·부분체결·미체결 반영 |
| 페이퍼 트레이딩 | 실계좌 투입 전 전략 검증. 장 시간 무관, 반복 실행 가능 |
| 스트레스 테스트 | 유동성 고갈·가격 역전 등 이상 상황에서 전략 반응 확인 |
| 집행 전략 실험 | 증권사 SOR이 내 전략에 유리한지 판단할 근거 확보 |

**핵심 산출물**: "낙관적 가정 대비 실제 예상 성과가 N% 낮다"를 수치로 제시한다.

---

## 설계 원칙

**전략 코드는 붙은 대상을 모른다.**

```
           [전략 엔진]
                │
      submit_order / cancel_order / on_execution
                │
     ┌──────────┴──────────┐
     │                     │
[토스증권 어댑터]      [mini-sor 어댑터]
   (실거래)             (검증·백테스트)
```

같은 전략 코드가 양쪽에서 수정 없이 돌아가야 한다. 이게 이 트랙의 성패를 가른다.

**시간은 주입받는다.**

백테스트는 3개월치를 몇 분에 돌려야 한다. 전략이 `now()`를 직접 호출하면 불가능하다.
시각은 전부 시계 객체를 통해 얻는다. 실거래에서는 실제 시각, 백테스트에서는 가상 시각을 주입한다.

## 작업 목록

### TB-01 브로커 인터페이스 정의
- [ ] 의존: T2-14

전략 엔진과 집행 계층 사이의 유일한 접점.

**완료 조건**
- 인터페이스 정의 (전략 엔진 언어 기준)
  - `submit_order(symbol, side, qty, order_type, price) -> order_id`
  - `cancel_order(order_id) -> bool`
  - `modify_order(order_id, new_price, new_qty) -> bool`
  - `get_position(symbol) -> position`
  - `get_balance() -> balance`
  - `on_execution(callback)` — 체결 통보 구독
  - `on_reject(callback)` — 거부 통보 구독
- 주문 유형 열거형은 **양쪽 구현체가 모두 지원하는 것만** 포함
  - 토스증권이 지원하지 않는 유형(중간가 등)은 인터페이스에 넣지 않는다
  - mini-sor 전용 기능은 별도 확장 인터페이스로 분리
- 시장 지정(KRX/NXT) 지원 여부를 먼저 확인하고, 미지원이면 인터페이스에서 제외
- 인터페이스 문서화: 각 메서드의 동기/비동기 여부, 실패 시 동작
- `test_broker_interface`: 더미 구현체로 전 메서드 호출 경로 검증

**선행 조사**: 토스증권 API의 주문 유형·응답 구조·에러 코드를 먼저 정리한다.
인터페이스가 실거래 쪽과 어긋나면 어댑터가 두꺼워지고, 전략 코드가 오염된다.

### TB-02 가상 시계
- [ ] 의존: TB-01

**완료 조건**
- `clock_t` 인터페이스: `now()`, `sleep_until(ts)`
- 구현체 2종
  - `real_clock` — 시스템 시각. 실거래용
  - `virtual_clock` — 주입된 논리 시각. 백테스트용
- 가상 시계는 배속 설정 가능 (1배속 / 무제한)
- 무제한 배속에서 `sleep_until()`은 즉시 반환하고 시각만 점프
- 이벤트 기반 진행: 다음 이벤트 시각으로 점프. 빈 구간을 실시간으로 기다리지 않는다
- `test_virtual_clock`: 3개월 구간을 무제한 배속으로 순회, 시각 단조 증가 검증

**주의**: 전략 코드에서 `time()`, `datetime.now()` 직접 호출을 전부 제거해야 한다.
기존 전략 코드 점검이 이 태스크에 포함된다.

### TB-04 백테스트 러너
- [ ] 의존: TB-03

## 우선순위 제안

두 목적이 한 코드베이스에 공존한다. 시간이 부족하면 나뉘는 지점이다.

| 목적 | 필요한 것 |
|---|---|
| 알고리즘 트레이딩 (개인 활용) | Phase 1 → Phase 2 → Track B |
| 증권사 IT 포트폴리오 | Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 |

**공통 구간이 Phase 1+2다.** 여기까지는 어느 쪽이든 필요하다.
이후 갈림길에서 지원 일정과 개인 활용 우선순위를 보고 선택한다.

Track B는 Phase 3~4보다 가볍다(4~6주 예상). 개인 활용을 먼저 보고 싶다면
Phase 2 → Track B → Phase 3 순서도 가능하다.
