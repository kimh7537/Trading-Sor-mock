# 작업 목록

각 태스크는 한 세션에 끝낼 수 있는 크기다.
완료 조건이 곧 테스트 명세다. 완료 조건에 없는 것은 만들지 않는다.

**진행 규칙**
- `[ ]` → `[x]`로 바꾸는 것은 전체 테스트 + ASan 통과 후에만
- 의존성(`의존:`)이 미완료면 해당 태스크를 시작하지 않는다
- 한 세션에 한 태스크

- `ts_t`를 받아 닫힌 시장은 제외한다 (`market_rules_t.is_open`)
- `test_consolidated.c`: 한쪽만 호가 있음 / 동률 / 시장 간 교차 / 닫힌 시장 제외 /
  빈 통합 호가창 / 10단 스냅샷의 가격·시장 순서

### T2-03 최선집행기준 평가
- [ ] 의존: T2-02

`sor/src/best_execution.c`

자본시장법 제68조의 최선집행의무를 점수로 환산한다. **이 프로젝트의 핵심 판단이다.**

**완료 조건**
- `venue_score_t` — 시장 하나에 대한 평가. 항목별 점수를 따로 보관한다
  (합계만 남기면 왜 그 시장을 골랐는지 설명할 수 없다)
- 평가 항목 넷: 가격 / 체결 가능성 / 비용 / 시장 상태
  - 가격: 최우선호가가 얼마나 유리한가
  - 체결 가능성: 요구 수량을 채울 수 있는 잔량이 있는가 (`book_qty_up_to`)
  - 비용: 수수료 차이 (시장별 파라미터)
  - 시장 상태: 열려 있는가, 스프레드가 비정상적으로 넓지 않은가
- `int be_evaluate(const cons_book_t *, const order_t *req, ts_t, venue_score_t out[MARKET_COUNT])`
- 점수는 정수다. 부동소수를 쓰면 같은 입력에 다른 순위가 나올 수 있다
- 동점이면 T2-01과 같은 규칙으로 시장을 고른다
- `test_best_execution.c`: 항목별로 한 시장이 이기는 경우 각각, 동점,
  닫힌 시장 제외, 잔량 부족

### T2-13 집행 품질 측정
- [ ] 의존: T2-08, T2-10

`sor/src/execution_quality.c`

**완료 조건**
- 평균 체결 단가 = 체결금액 / 체결수량 (정수 연산)

- `test_execution_quality.c`: 손으로 계산한 값과 정확히 일치
